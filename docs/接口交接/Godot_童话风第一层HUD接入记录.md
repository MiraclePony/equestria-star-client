# Godot 纸艺风游戏 HUD 接入记录

更新时间：2026-11-17。

## 来源与迁移边界

- 视觉来源固定为 `MiraclePony/equestria-star-client` 的 `ui/paper-hud` 分支、提交 `2f46d1f865ae8853d17d0ab4370ba530f75c12bf`。
- 本项目未合并分支、未 cherry-pick，也未用来源项目场景或业务脚本整文件覆盖本地实现。
- 仅提取并由当前 Godot 工程重新导入：64 张 `paper_hud` 透明 PNG、20 张角色头像、34 张伙伴卡图和 1 张伙伴卡背；未复制来源 `.godot` 缓存或 `.import` 文件。
- 本地未提交的商店、任务、道具、判定、移动、心跳和原请求恢复逻辑均作为业务基线保留。

## 第一层布局与权威数据

- 左侧：纸艺回合名牌使用真实 `turnOrder` 排序，当前行动者只读取服务端 `currentTurnUserId`；“下一位”“已行动”仅保留可复用样式，不由客户端推算或点亮。
- 底部：当前玩家头像、姓名、金币、声望、有效六维，以及伙伴、道具、装备、个人任务入口。正式伙伴栏固定为 3 槽，不采用来源分支早期的 5 槽设计。
- 右侧：公共任务板和公共货架纸艺抽屉。单卡接取/购买与抽屉底部的出售、刷新货架、刷新任务板保持分离。
- 右下：行为折叠菜单保留打工、铁路、判定和提交；结束回合改为独立圆章，并且是唯一入口，继续沿用原资格、提交中状态和防重复提交。
- 顶部：聊天抽屉仅显示未开放占位，不发送消息；行动历史抽屉只在打开时调用既有只读 `action-logs` 接口。
- 伙伴卡图只按 `partnerCode` 查询映射，不按中文名猜测。未知编码显示卡背并输出诊断；正式线上编码清单仍需真实服务数据核对。

## 本地业务能力保留

- 公共任务板仍支持接取和刷新任务板；公共货架仍支持购买、出售道具和刷新货架。
- 出售确认与成交结果继续使用服务端 `itemSell.itemName`、`itemSell.sellPrice`；确认成功后的只读刷新失败不会抹掉成交结果。
- 两种刷新、出售和放弃任务继续沿用原 `requestId`、原路径与完整原请求体恢复边界；打开抽屉本身仍是只读 GET，不会产生付费刷新。
- 个人任务、背包、装备、奖励、骰子、判定及其他二级界面保留原有外观和业务逻辑，本次只替换第一层 HUD 与公共抽屉外框。

## 输入与生命周期

- 透明布局和纯装饰节点使用 `MouseFilter.Ignore`；实际按钮、玩家条目、抽屉和遮罩继续加入 `blocks_map_input`。
- 菜单收起后不保留隐形命中区域。按钮依赖 Godot 原生 `Pressed`，不在按钮自身 `GuiInput` 阶段提前消费鼠标事件。
- 伙伴预览只在权威玩家视图版本变化时刷新，不新增定时轮询；行动历史只在用户打开抽屉时查询。
- 玩家视图轮询继续复用同一玩家条目，悬停详情跨刷新保持稳定并更新数值；玩家移除、移出或 HUD 清理时关闭详情。
- 公共抽屉采用确定性安全矩形，不再通过将容器 `Size` 清零来定位，避免重复打开或刷新后按钮逐次漂移出窗口。

## 验证边界

- 自动化与模拟传输只验证客户端布局、GUI 分发、请求次数和既有业务绑定，不代表真实服务联调。
- 本次未登录或操作真实对局，未发送接取、购买、出售、刷新或结束回合等线上写请求。
- 实际窗口验收覆盖 1920×1080 和 960×540；真实鼠标覆盖行为菜单、聊天/历史抽屉、货架、出售确认及取消。其余线上业务结果仍由用户在现有对局中手动验收。
