## 实现方式

### 游戏内专用主题 `assets/theme/ingame_paper_theme.tres`

只挂在游戏内覆盖层根节点（个人任务、伙伴、判定、交付、卡牌查看层、骰子层、HUD），入口页仍用 `client_theme.tres`。C# 动态创建的控件自动继承。

| 类型 / 变体 | 用途 |
| --- | --- |
| `Button` | 主操作：金色纸胶囊；禁用为中性灰 + 灰字 + 灰图标；金色焦点外圈；图标统一最大 26px |
| `PaperSecondaryButton` / `PaperCloseButton` | 取消、返回、否 / 关闭（带 ✕ 图标） |
| `PaperDangerButton` | 放弃、丢弃、遣散 |
| `PaperTitleLabel` | 标题：圆润粗体 + 桃色折角纸签底 |
| `PaperMutedLabel` / `PaperErrorLabel` | 状态提示 / 错误与不可用原因（砖红） |
| `PaperSummaryLabel` | 结算摘要卡片底 |
| `PanelContainer` / `PaperCardPanel` / `PaperNoticePanel` / `PaperBarePanel` | 手撕纸主面板 / 带蜂蜜金色条的信息卡 / 行内提示条 / 仅接收输入的透明外层 |
| 滚动条、输入框、悬停提示、分隔线 | 暖米色轨道 + 驼色滑块、暖纸输入框、奶油提示框、带星星的分隔纸条 |

### 场景与动态控件

- `tools/ui/repaper_scene.py`：场景主题替换、去掉深色底配色覆盖、按节点名加主题变体、遮罩改暖棕半透明。骰子层面板保留原内边距（只换外观），避免改变投掷区与按钮命中。
- `tools/ui/add_button_icons.py`：给场景中的静态按钮挂操作图标（只加 `icon` 属性）。
- 动态卡片、按钮在创建处只加 `ThemeTypeVariation` / `Icon` / 纸面配色；枚举显示（道具类型、位置、属性名）改为中文，仅用于显示（`PaperDisplayText.cs`），不参与判断。
- 状态提示统一预留两行高度，文字变长不再推动面板跳动（对应 H02）。

### 骰子层“大骰判定”二维演出 `WorkDiceOverlay.Presentation.cs`

- 四周压暗、难度徽章 + 属性签、停骰点数气泡、成功 / 失败缎带与回执算式（骰点 + 属性值 ± 修正 = 总值 · 难度，缺字段则不显示该项）；森林方向骰显示“已抵达 / 原地停留”。
- 新节点全部 `MouseFilter.Ignore`、不加入 `blocks_map_input`；首次需要时才创建；动画在关闭、重开时 Kill，不留 Tween。
- 原 `ResultLabel` 文字与所有状态切换保持不变。

## 测试修复（只改测试的时序，不改断言）

- `RunWorkFlowTests` / `RunGameScreenTests` 的“点击控件”辅助函数原先只等一帧就读取按钮位置；面板刚显示时容器布局（含居中）可能还要两三帧才排定，点击会落到旧位置。改为等控件位置连续 3 帧不变再点。基线上这两个测试本就时好时坏，纸艺面板排版略慢使失败更频繁。
- `RunWorkFlowTests` 关闭结果页的三处点击前先等 50 毫秒真实时间：结果页只接受“结果出现之后的新点击”，无界面测试一帧可能不到 1 毫秒。
- 超时信息带上调用行号，便于定位。
- 修复后对照：打工流程测试基线骰子层 8/8、本分支 8/8；GameScreen 8/8。

## 发现的业务问题（未修改，请项目所有者决定）

- **打工结果页偶发无法关闭**（`scripts/ui/GameScreen.Work.cs`）：结果页显示的同时，后台“恢复待判定”流程并发运行，骰子层状态被来回切换；结果页的“延迟武装”执行时状态不是“结果”，切回“结果”后没有重新武装，玩家点击被忽略并随后进入“恢复错误”。修复后的测试中约 1/14 复现。按交接文档，业务层改动需先由项目所有者确认。
- `RunQuestCheckTests` 偶尔在退出时打印 Godot 引擎内部的 `Handle is not initialized`，测试本身通过，与本轮改动无关。
