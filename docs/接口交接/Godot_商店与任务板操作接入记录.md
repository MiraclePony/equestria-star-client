# Godot 商店与任务板操作接入记录

更新时间：2026-11-14。

准确费用、资格和响应字段仍以 `ES完整API文档.md` 为准。本记录只描述客户端当前接入边界，不代表真实服务写操作已经验收。

## 当前接入

- 公共货架打开时只执行 `GET /games/{gameId}/shop/current`。玩家确认后才发送 `SHOP_REFRESH {}`；确认前再次同步玩家视图和 `available-actions`，不在客户端计算费用或抽牌。
- 公共任务板打开时只执行 `GET /games/{gameId}/quest-offers`。独立「刷新任务板」按钮按 `REFRESH_QUEST_OFFERS` 资格启用；确认后发送空 payload，成功后重新 GET 整板候选，不传单卡 ID、不本地补牌。
- 两个刷新确认框分别展示 2 社交点和 1 社交点费用。取消只关闭确认层并保留原列表，不发送写请求。
- `SHOP_SELL_ITEM` 使用持有实例 `playerItemId`；成交提示只读取成功回执 `itemSell.itemName/sellPrice`，不使用确认前预览值。
- `ABANDON_QUEST` 使用 `questId + playerQuestId`；确认前不预扣声望、不移除任务，成功后重新读取个人任务与玩家视图。

## 未知结果恢复

- 本记录四项写操作遇到超时、断线、空响应、回执解析失败或 `REQUEST_IN_PROGRESS` 时，自动以原路径、原 `requestId` 和完整原请求体恢复一次。
- 自动恢复后仍未知时，保留原请求并提供人工「恢复原操作」。关闭并重开弹层仍优先展示该未决请求，不能生成新的同类扣费操作。
- 明确业务拒绝不自动重发；版本过期先同步；请求 ID 冲突不更换 ID。成功后的列表 GET 失败只重做只读同步。
- 历史回执可以确认原操作，但玩家视图仍受版本下限保护，不能覆盖更高版本状态。

## 验证边界

- 本地模拟必须区分 HTTP 请求次数和服务端副作用次数，模拟“首次回执丢失但服务端已执行”时，第二次同 ID 返回原结果且副作用仅一次。
- GUI 验证使用 Viewport 的实际鼠标按下/释放路径；直接发射 `Pressed` 仅可作为业务单元测试补充。
- 未经授权不登录或操作真实对局；本地模拟和窗口检查均不等于线上联调。
